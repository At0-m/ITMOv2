## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- API-1: diff длиннее 20 000 символов должен отклоняться с HTTP 413.
- REL-1: вызов внешнего LLM должен иметь timeout 10 секунд; ошибка превращается в контролируемый ответ.
- OUT-1: результат содержит summary, risks (до 3) и checks. В risks поля: file, line, evidence, risk.
- SCOPE-1: сервис только советует и не выполняет действия в GitHub.
- QA-1: риск включают только при подтверждении строкой diff или правилом.
- OBS-1: логируются только request_id, длительность и статус, без содержимого diff и ответа.

### Формат входа и результата

- Вход: текстовый diff PR.
 - Результат: JSON со структурой { summary, risks[], checks[] } согласно OUT-1. В risks до 3 элементов с file, line, evidence, risk. Решение принимает человек‑ревьюер.

### Ограничения и запрещённые действия

- Нельзя передавать секреты во внешний LLM (SEC-1).
- Нельзя принимать diff > 20 000 символов, должен быть 413 (API-1).
- Соблюдать SCOPE-1: без approve/merge/изменения кода.
- Нельзя логировать содержимое diff и ответ модели (OBS-1).

### Хороший пример

app/review_service.py:14 — в prompt подставляется сырой diff, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt вместо токена попадает [REDACTED].
### Плохой пример

«Код можно улучшить. Добавьте обработку ошибок.» — нет файла/строки, нет применимого правила и воспроизводимой проверки.
### Что пока неизвестно

- Конкретная модель/провайдер LLM.
- Требуемая минимальная версия Python и политика async/sync.
- Политика аутентификации/квотирования API.
- Схема response контракта в OpenAPI (сейчас отсутствует в diff).
