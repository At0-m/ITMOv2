Feature A — Input validation

Пользователь вводит цену автомобиля в JPY.

Acceptance criteria:
1. Цена обязательна.
2. Цена должна быть числом.
3. Цена должна быть больше 0.
4. Цена не должна превышать 100000000 JPY.
5. Невалидный ввод показывает понятную пользователю ошибку.
6. При невалидном вводе сервис расчёта стоимости не вызывается.

Проверяемые сценарии:
- валидная цена -> сервис вызывается;
- пустое значение -> ошибка, сервис не вызывается;
- 0 -> ошибка, сервис не вызывается;
- отрицательное значение -> ошибка, сервис не вызывается;
- значение больше 100000000 -> ошибка, сервис не вызывается;
- нечисловое значение -> ошибка, сервис не вызывается.

Feature B — Dependency error

После валидного ввода используется сервис расчёта стоимости.

Acceptance criteria:
1. Ожидание сервиса ограничено по времени.
2. Timeout показывает понятную пользователю ошибку.
3. Другая ошибка сервиса показывает понятную пользователю ошибку.
4. Все сценарии Feature A сохраняют прежнее поведение.

Проверяемые сценарии:
- успешный ответ -> результат отображается;
- timeout -> отображается timeout error;
- reject/error -> отображается dependency error;
- невалидный ввод по-прежнему не вызывает сервис.
