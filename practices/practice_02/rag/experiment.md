## Запрос

Сопоставить сценарии и метрики в @practices/practice_01/tests_load.md с правилами и решениями из @practices/practice_01/CASE.md, @practices/practice_01/README.md и @practices/practice_01/adr.md; для каждого пункта указать, подтверждён он источниками или является предлагаемым/неподтверждённым.

## Ответ со ссылками на источники

Подтверждённые требования/ограничения:
- Граничная логика размера diff: «diff длиннее 20 000 символов отклоняется с HTTP 413». Источник: @practices/practice_01/CASE.md, правило API-1 (строка 65); дублируется в @practices/practice_01/adr.md (строка 12).
- Таймаут вызова внешнего LLM: «timeout 10 секунд; ошибка превращается в контролируемый ответ». Источник: @practices/practice_01/CASE.md, правило REL-1 (строка 66); подтверждено в @practices/practice_01/adr.md (строки 9, 12).
- Ограничение на evidence/логирование: «в лог пишутся только request_id, длительность и статус; содержимое diff и ответа модели не логируется». Источник: @practices/practice_01/CASE.md, правило OBS-1 (строка 70). Это влияет на допустимые виды evidence в нагрузочных отчётах.
- Назначение файла tests_load.md как места фиксации «нагрузочные проверки и ожидаемые пределы». Источник: @practices/practice_01/README.md (строка 43). Численные пределы в README не заданы.

Неподтверждённые или предлагаемые пункты из @practices/practice_01/tests_load.md:
- Профиль нагрузки «10 RPS, 5 минут» для валидных диффов — неподтверждённое (источники не содержат RPS/длительности). Ссылка на формулировку: @practices/practice_01/tests_load.md (строка 5).
- Цели производительности «p95 < 2с, ошибки < 1%» — неподтверждённое (в источниках нет SLA/порогов по латентности/ошибкам). Ссылка: @practices/practice_01/tests_load.md (строка 5). Присутствует только общий таймаут 10с (REL-1), который не устанавливает p95.
- Профиль на границе лимита «2 RPS, 2 минуты, длина 19 500–20 500» — неподтверждённое (источники не задают RPS/длительности/диапазоны). Ссылка: @practices/practice_01/tests_load.md (строка 6).
- Требование «0% ошибок для ≤20 000» — неподтверждённое. Источники подтверждают только отказ >20 000 с 413 (API-1), но не гарантируют нулевую ошибочность для любых входов ≤20 000. Ссылка: @practices/practice_01/tests_load.md (строка 6); подтверждённая часть — «100% 413 для >20 000» из @practices/practice_01/CASE.md (строка 65).
- Раздел «SLA не задан… Нагрузочное тестирование имеет смысл при появлении профиля…» — часть «SLA не задан» согласуется с отсутствием SLA в источниках; вывод про «когда имеет смысл» является предлагаемым комментарием, не подтверждённым правилами. Ссылка: @practices/practice_01/tests_load.md (строки 8–9).
