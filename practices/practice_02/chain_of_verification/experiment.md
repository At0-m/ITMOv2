## Проверки по утверждениям (claim → evidence → check)

1) claim: AS IS — Пользователь отправляет HTTP POST на /api/reviews с JSON {"diff": "..."}; синхронный обработчик напрямую вызывает ReviewService.review; ответ имеет вид {"comment": str}.
   evidence: TRAINING_PR.diff:
   - app/api.py:35-37 — объявлен маршрут @app.post("/api/reviews"), тело обрабатывается как dict, вызывается review_service.review(payload["diff"]).
   - app/review_service.py:19-22 — метод review формирует prompt, вызывает llm.generate и возвращает {"comment": answer}.
   check: Запустить приложение и отправить запрос.
   - Команда: uvicorn app.api:app --reload
   - Запрос: curl -s -X POST http://localhost:8000/api/reviews -H 'Content-Type: application/json' -d '{"diff":"demo"}'
   - Ожидание: 200 OK и JSON со структурой {"comment": ...}. Для детерминированности можно подменить LLM в зависимостях на фейковый, возвращающий фиксированную строку.

2) claim: AS IS — В diff не указана FastAPI response_model; возвращаемая структура {"comment": ...} не соответствует OUT-1.
   evidence:
   - TRAINING_PR.diff app/api.py:35-37 — отсутствует параметр response_model у @app.post; сигнатура функции указывает лишь тип возврата Python (dict[str, str]).
   - CASE.md:67 — OUT-1 требует поля summary, risks[], checks[].
   check: Отправить POST как в (1) и убедиться, что в ответе присутствует ключ comment и отсутствуют summary/risks/checks; сравнить с JSON-схемой OUT-1 из CASE.md.

3) claim: AS IS — Сырый diff отправляется во внешний LLM без редактирования секретов (SEC-1 не реализован в показанном diff).
   evidence: TRAINING_PR.diff app/review_service.py:20-22 — prompt включает diff целиком; нет вызова редактирования/маскировки.
   check: Юнит-тест с фейковым LLM, который возвращает принятый prompt. Передать diff с тестовым секретом (например, "token=ABC"); проверить, что llm.generate был вызван с prompt, содержащим исходное значение, а не [REDACTED]. Ожидаемо в текущем коде секрет не маскируется.

4) claim: AS IS — Таймаут LLM-вызова отсутствует; возможна долгая задержка/зависание.
   evidence:
   - TRAINING_PR.diff app/review_service.py:21 — вызывается self.llm.generate(prompt) без параметров таймаута и без обёртки с ограничением времени.
   - CASE.md:66 — REL-1 требует timeout 10 секунд и контролируемую ошибку.
   check: Интеграционный тест с LLM-заглушкой, которая sleep(15). Ожидание в текущем коде: запрос будет ждать >10s, не возвращая контролируемый ответ. Это демонстрирует отсутствие реализации REL-1.

5) claim: AS IS — Лимит размера diff отсутствует; при длине > 20 000 символов не вернётся 413 (API-1 не реализован в показанном diff).
   evidence:
   - TRAINING_PR.diff app/api.py:35-37 — отсутствует любая проверка длины payload["diff"].
   - CASE.md:65 — API-1 требует 413 при diff длиннее 20 000 символов.
   check: Отправить POST с полем diff длиной 20 001 символ. Ожидание в текущем коде: не 413; ответ 200/500 в зависимости от других факторов. Это подтверждает отсутствие лимита.

6) claim: AS IS — Возможен 500 при невалидном вводе (нет валидации тела запроса).
   evidence: TRAINING_PR.diff app/api.py:36-37 — доступ к payload["diff"] без схемы/валидации; при JSON {} произойдёт KeyError внутри обработчика.
   check: Отправить POST на /api/reviews с пустым JSON {}. Ожидание: 500 Internal Server Error вместо 422 свалидированных ошибок, что подтверждает отсутствие модели/валидации запроса.

7) claim: AS IS — В показанном diff не видно реализации OBS-1 (логирование только request_id, длительность, статус).
   evidence:
   - TRAINING_PR.diff — отсутствуют строки логирования; по предоставленному diff подтвердить реализацию OBS-1 нельзя.
   - CASE.md:70 — OBS-1 определяет требование к логированию.
   check: Требуется отдельная проверка кода логирования за пределами данного diff (поиск по репозиторию и анализ конфигурации логов). По текущим источникам утверждение о несоблюдении/соблюдении OBS-1 не подтверждается; зафиксировано как «evidence отсутствует».

8) claim: TO BE — Минимально жизнеспособный процесс: валидация входа и размера diff (API-1), редактирование секретов (SEC-1), таймаут LLM 10s и контролируемая ошибка (REL-1), возврат структуры OUT-1.
   evidence: CASE.md:64-71 — формальные правила SEC-1, API-1, REL-1, OUT-1, OBS-1, QA-1.
   check: Набор проверок, соответствующий «Разница» в analysis.md: интеграционный тест на 413 при >20k; юнит-тест редактирования секретов; интеграционный тест с искусственной задержкой для таймаута; E2E-тест на соответствие OUT-1. Эти проверки воспроизводимы и напрямую соотносятся с правилами CASE.md.

## Исправленный результат

- Подтверждено по источникам (TRAINING_PR.diff, CASE.md): маршрут /api/reviews, прямой вызов ReviewService.review, ответ {"comment": ...}; отсутствие response_model и несоответствие OUT-1; отсутствие явной редакции секретов, лимита размера и таймаута в показанном diff; риск 500 при невалидном вводе.
- Скорректировано: формулировку про OBS-1 фиксируем как «в показанном diff не обнаружено evidence реализации OBS-1» без вывода о состоянии во всём репозитории.
- TO BE корректно опирается на CASE.md (SEC-1, API-1, REL-1, OUT-1); требуется реализация и покрытие указанными проверками.
