# Few-shot

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Артефакт Практики 1: practices/practice_01/tests_integration.md (таблица Integration-проверки)
- Что хотим улучшить: сделать сценарии атомарными (один сценарий — одна причина отказа), убрать смешивание «нет diff или таймаут», уточнить Evidence по CASE.md

## Примеры

### Хороший результат

| Связь компонентов | Что может сломаться | Как воспроизводим | Ожидаемый результат | Evidence |
|---|---|---|---|---|
| FastAPI handler | Отсутствует поле diff | Отправить payload без ключа diff | Предлагаемое поведение: 422 Unprocessable Entity | HTTP 422 и тело с описанием валидации |
| ReviewService -> LLM Adapter | timeout LLM | stub отвечает дольше 10 секунд | Контролируемый ответ по REL-1; структура OUT-1 соблюдена | HTTP-ответ + время вызова (~10с) |
| ReviewService -> LLM Adapter | Утечка секретов | Отправить diff с тестовыми токенами/секретами | В prompt исходное значение секрета отсутствует в payload, отправляемом внешнему LLM (SEC-1) | Перехват payload мока/адаптера; отсутствие секретов |
| FastAPI handler | Превышение размера входа | Отправить diff > 20 000 символов | 413 Payload Too Large (API-1) | HTTP 413 |

Перепиши таблицу из practices/practice_01/tests_integration.md так, чтобы каждый сценарий был атомарным: один сценарий — одна причина отказа. Используй только требования из practices/practice_01/CASE.md (SEC-1, API-1, REL-1, OUT-1, QA-1, OBS-1). Ничего нового не придумывай.

Требования к результату:
- Таблица с колонками: «Связь компонентов | Что может сломаться | Как воспроизводим | Ожидаемый результат | Evidence».
- Раздели смешанный сценарий «нет diff или таймаут» на два отдельных: «отсутствует diff» и «timeout LLM».
- Ожидаемые результаты ссылайся на правила из CASE.md (например, API-1, REL-1, SEC-1, OUT-1).
- Evidence должен быть наблюдаемым и не нарушать OBS-1 (без логирования содержимого diff/ответа модели).
- Язык: русский. Формат: Markdown-таблица.
