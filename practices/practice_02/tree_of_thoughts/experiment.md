# Tree of Thoughts

- Решение, для которого нужны альтернативы:
Архитектура AI code review сервиса для анализа diff (слой предобработки + LLM-адаптер из ADR Практики 1).
- Критерии выбора:
соответствие CASE.md (SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1); безопасность; надёжность; сложность реализации; проверяемость.

## Запрос

Сформулировать и сравнить три архитектурные альтернативы A/B/C для AI code review в рамках правил CASE.md, оценить по заданным критериям и выбрать одну. Новых требований вне CASE.md не добавлять.

## Внешне описанные альтернативы

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A | Минимум кода и интеграции; быстрое внедрение; меньше точек отказа | Риски утечки секретов (нет уверенной редакции); возможны подвисания и нестабильный формат; частичное нарушение CASE; слабая воспроизводимость | CASE: частичное; Безопасность: низкая; Надёжность: низкая; Сложн: низкая; Проверяемость: низкая |
| B | Максимальная защита и предсказуемость; fail-closed; строгая схема/валидация; простые детерминированные тесты | Высокая трудоёмкость и время; риск оверинжиниринга для учебного кейса; возможны ложные срабатывания агрессивной редакции | CASE: полное; Безопасность: высокая; Надёжность: высокая; Сложн: высокая; Проверяемость: высокая |
| C | Соблюдает CASE при умеренной сложности; детерминированный pre-processing и адаптер с таймаутом; хорошая тестируемость | Не покрывает экзотические форматы секретов; зависимость от стабильности LLM ответа сглаживается нормализацией; меньше резервов, чем у B | CASE: полное; Безопасность: высокая; Надёжность: средняя-высокая; Сложн: средняя; Проверяемость: высокая |

## Выбор

- Выбранная альтернатива:
C — balanced.
- Почему:
Полностью соблюдает CASE.md при разумной сложности; закрывает ключевые риски (SEC-1, REL-1, API-1) без избыточной инфраструктуры; хорошо проверяема за счёт явной нормализации OUT-1 и детерминированной редакции секретов.
- Как проверим:
>20k символов даёт 413 (API-1); таймаут 10с маппится в контролируемый ответ (REL-1); секреты редактируются до вызова LLM (SEC-1); ответ соответствует OUT-1 и включает максимум 3 risks с обязательным evidence по QA-1; лог только request_id/длительность/статус (OBS-1); SCOPE-1 соблюдён (нет действий вне советов).
