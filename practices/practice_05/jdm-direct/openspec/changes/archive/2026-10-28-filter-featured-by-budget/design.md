# Design

## Context

Требуется клиентская фильтрация Featured JDM по целочисленному бюджету JPY без бэкенда. DOM остаётся в `src/main.ts`. Новую доменную логику выносим в чистые функции без зависимостей от DOM и калькулятора: `validateBudget(value: string): { ok: true, value: number } | { ok: false, code: 'nan'|'nonpositive'|'fraction'|'too_large' }` и `filterCarsByBudget(cars, budgetJpy?: number): cars`. Пустое/пробельное значение при submit трактуется как отсутствие фильтра: ошибки нет, отображается полный каталог в исходном порядке.

## Goals / Non-Goals

**Goals:**
- Валидация ввода бюджета по требованиям (целое 1..100000000, JPY).
- Инклюзивная фильтрация по `priceJpy <= budget` с сохранением исходного порядка.
- Чистые функции без DOM-зависимостей и без изменения калькулятора.

**Non-Goals:**
- Любые изменения калькулятора (Feature A/B), `src/priceValidation.ts`, backend/API, URL state, сортировка, поиск, другие фильтры.

## Decisions

1. Разделение: валидация и фильтрация вынесены в модуль `src/budgetFilter.ts` c чистыми функциями. Это позволяет юнит-тестировать без DOM и сохранить `src/main.ts` простым.
   - Альтернатива: инлайн-логика в `src/main.ts` — хуже для тестируемости и повторного использования.
2. Семантика пустого ввода: при submit трактуется как отсутствие фильтра, ошибок нет, отображается полный каталог в исходном порядке (это может изменить текущую выдачу, если до этого был активен фильтр).
3. Обработка невалидного ввода: показываем ошибку и не меняем текущий набор (стэйт списка неизменен).

4. Маппинг ошибок (UI):
   - `nan` → "Неверное значение бюджета"
   - `fraction` → "Дробные значения JPY не допускаются"
   - `nonpositive` → "Допустимый диапазон: 1 — 100000000 JPY"
   - `too_large` → "Допустимый диапазон: 1 — 100000000 JPY"

5. Формат цены на карточке: `Intl.NumberFormat('ru-RU').format(priceJpy) + ' JPY'` (например, "5 800 000 JPY").

6. Reset-контрол: доступен при любом активном непустом валидном фильтре, включая состояние без результатов; по нажатию очищает input и error, скрывает empty state, возвращает полный каталог в исходном порядке; после reset сам контрол скрывается.

## Risks / Trade-offs

- Ошибки локализации сообщений. Митигация: коды ошибок из `validateBudget`, маппинг в UI.
- Сохранение исходного порядка: фильтрация должна быть стабильной. Митигация: не сортировать, использовать `.filter` над исходным массивом.

## Migration Plan

- Добавить модуль с чистыми функциями, покрыть юнит-тестами (граница включительно, невалидный ввод, empty/no-filter).
- Интегрировать вызовы в `src/main.ts` за флагом (если нужен) или напрямую — без изменения остальной архитектуры.

## Verification Strategy

- Не добавляем jsdom или другие новые зависимости ради этой фичи.
- Юнит-тестами покрываем чистую логику `validateBudget` и `filterCarsByBudget`.
- Наблюдаемое UI‑поведение проверяется отдельно в браузере на acceptance‑этапе.
- `scripts/check.sh` продолжает выполнять автоматические тесты и сборку.
