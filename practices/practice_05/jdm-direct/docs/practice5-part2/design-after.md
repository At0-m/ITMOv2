# Design: Featured Compare (AFTER)

## Context
Раздел Featured JDM отображает статический список демо‑авто с локальными данными и уже поддерживает фильтрацию по бюджету. Необходимо добавить лёгкое сравнение автомобилей без изменения существующего калькулятора и без backend.

## Goals
- Выбор до двух автомобилей из Featured для сравнения.
- Отображение сравнения только при ровно двух выбранных.
- В сравнении показывать: название, цену (JPY) и основные характеристики.
- Сосуществование с текущим фильтром по бюджету без изменения его поведения.

## Non‑Goals
- Нет сетевых запросов/интеграции с backend.
- Нет расширения модели данных за пределами уже имеющегося списка Featured.
- Нет поддержки сравнения более чем двух автомобилей.
- Нет изменений калькулятора и правил валидации из docs/requirements.md.

## Approach
Добавить к карточкам Featured минимальный управляющий элемент выбора (чекбокс/переключатель). Поддерживать локальное множество выбранных ID. Сравнение рендерить как отдельный UI‑блок/панель, который становится видим только при count(selected) == 2. Таблично отобразить пары полей (title, priceJpy, meta) для двух выбранных автомобилей.

## State: selected car IDs
- selected: Set<string> идентификаторов выбранных автомобилей.
- Инварианты:
  - 0 <= size(selected) <= 2.
  - Попытка добавить третий ID отклоняется (состояние не меняется).
  - Снятие выбора удаляет ID из множества.

## Interaction: cards, selection, comparison UI
- Карточка содержит контрол выбора и визуальное состояние выбранности.
- При size(selected) < 2: элементы сравнения скрыты.
- При size(selected) == 2: показывается comparison UI с двумя колонками — по одному авто на колонку; строки: название, цена (форматированная JPY), характеристики.
- Пользователь может снять выбор из карточки или из comparison UI — состояние и UI обновляются синхронно.

## Filtering coexistence
- Бюджетный фильтр сохраняет текущее согласованное поведение, данных и сообщений.
- Выбор автомобилей не инициирует сетевых запросов и не изменяет логику фильтра.
- При применении или сбросе фильтра сравнение продолжает подчиняться правилу «видимо только при двух выбранных»; если выбранный автомобиль больше не отображается из‑за фильтра, UI сравнения скрывается, пока не будет снова выбрано два отображаемых автомобиля.

## Component Interaction (Mermaid)
Визуализация уже описанного взаимодействия компонентов/состояний:

```mermaid
flowchart TD
  BF[Budget filter] --> VF[Visible Featured cards]
  FC[Featured cards (all)] --> VF
  VF --> SEL[Selection state<br/>(selected IDs, max 2)]
  SEL -->|size == 2| COMP[Comparison UI<br/>(title, price JPY, key specs)]
  SEL -->|size < 2| HIDDEN[Comparison hidden]
```

## Key Decisions & Trade‑offs
- Жёсткий лимит в 2 авто упрощает макет и мобильную вёрстку; отказ от 3+ снижает сложность.
- Полная клиентская реализация исключает сетевые задержки и упрощает тестирование, но ограничивает данные текущим списком.
- Сокрытие сравнения при <2 выбранных избавляет от промежуточных состояний, но требует очевидной индикации выбранности на карточках.

## Accessibility (кратко)
- Нативный контрол выбора с меткой, фокус видим.
- Кнопки/ссылки сравнения доступны с клавиатуры.
